# 建模、数据与实验

工作深度服从任务、风险和剩余时间，不把通用建模教材重新写入上下文。

## 1. 数学抽象

选模型前识别问题结构、变量、假设、目标/约束、输入输出、估计方法与验证办法。
只把影响本题的内容写入模型 Evidence；不要求每次回复固定十问。
评价不等于自动套 TOPSIS，预测不等于自动套神经网络，优化不等于自动套遗传算法。
已有决策执行中不反复发散；发现实质不适用证据时走 Decision 重开。
候选方案可在授权范围内分析和试验；首次正式采用或实质变更主模型、关键假设、
目标/核心约束等，须先按 [user-intent.md](user-intent.md) 核对用户确认，再记录正式 DEC。
不能先把试验方案作为当前主路线执行，再补问用户或补写批准记录。

Baseline 是简单可用的对照和回退，不是强制线性模型，也不要求一定比后续模型差。
用户要先试复杂模型时按 [user-intent.md](user-intent.md) 评估实际风险，不直接拒绝。
改进要说明解决的问题、成本和验证标准；没有收益可以保留 Baseline。

正式大计算前，在模型 Evidence 中明确适用的执行契约：决策时点、可用信息、
允许修改的变量、执行规则、目标与实际评价指标、边界状态、输出要求。
区分规划量与实际执行量、预报发布日期与目标时刻、优化附加项与实际结算。
先用短例、边界或可行性复算检查模型是否符合题面允许的动作，再扩大计算。
不同问题统一单位、符号语义与接口；信息条件不同可以采用不同参数或方法，
不为了形式统一而强改模型，也不把跨问总差值直接解释为单一机制贡献。

## 2. 数据与推导

最先核对来源、字段语义、单位、主键/时间轴、缺失和明显异常。
根据任务补分布/相关/可视化，不把全部 EDA 设成一切建模的硬前置。
训练/验证划分、数据变换的拟合范围、时间和空间依赖须明确，避免泄漏。
信息使用分开核对：

- 执行：每次决策是否只读取当时可获得的观测与已发布预测；必要时截断/污染未来输入对照。
- 选择：参数、模型结构和候选选择是否使用报告性能的评价数据。
- 研发：反复看过评价结果后是否调整网格、方案或评价口径。删除评分代码、固定参数或
  后来重跑训练流程，不自动消除此前选择影响；不能因此宣称完全独立样本外验证。

时间相关任务按适合的滚动起点与预测提前期回放，不随意随机拆分相关时段。
闭环候选各自维护状态与反馈历史，不能复用另一候选受动作影响的执行记录。
特定月份训练只属于具体赛题安排，不写成所有建模问题的固定划分。
异常值先区分错误、测量异常、合理极值和特殊状态，处理理由可追溯。
raw 保持原样，处理由可复现脚本生成，记录数据版本和单位转换。

公式说明变量范围、量纲、约束和成立条件，并映射到实现。
解析问题保存推导和边界对照；不得为了满足“必须有代码”而伪造运行过程。
来源、引用或规则不确定时用可用工具查证；受赛事限制的资料不得借 Research 绕过。

## 3. 实验与输出契约

先说明实验要检验的假设及成功标准，再运行。
关键参数保留含义、单位/范围、来源类别、确定方法、选择数据范围/时点、
更新规则与适用版本。来源区分题面、推导、文献、校准、经验设置与在线估计；
沿用参数还要追溯其选型依据。记录可放在已有模型说明/运行配置，Evidence 引用即可。
经验值不得为了论证充实而改写成校准所得；固定分位水平不等于风险量不再更新。
记录输入版本、参数、随机种子（若适用）、环境/依赖版本、入口命令、
退出状态、实际输出位置、指标定义/单位、日志和耗时。
失败实验同样记录真实状态；批量调参可用一个 EXP + 机器可读运行清单，
不强制每组参数建立一个 Markdown。

按题型定义产物，不统一要求 predictions：

| 类型 | 常见必要产物 |
|---|---|
| 预测 | 样本/时间索引、真实值/预测值、数据划分和误差指标 |
| 优化 | 决策变量、目标值、约束残差、可行性、终止/最优性信息 |
| 评价 | 指标方向、归一化/权重、得分排名及稳定性 |
| 仿真 | 参数、时间步/收敛、轨迹和守恒/边界检查 |
| 解析 | 推导、适用假设、边界/特殊情形及核对依据 |

重要结果落可机器读取的文件，Evidence 引用该文件/字段；summary 是视图而不是第二份真值。
参数、运行产物和图表按版本保存，避免新试验覆盖论文已用文件。

## 4. 对比与验证

比较模型时尽量使用相同数据版本、划分、指标定义和求解预算；不可比处明确披露。
同时核对初末边界、信息集、实际执行规则、费用口径与反馈状态。
同条件机制对照回答增量贡献；参数敏感性回答扰动稳定性，不替代独立选参。
理想信息或约束松弛界仅在其假设下作为界限，不与受限信息策略作直接公平排名。
多机制逐项替换需注明顺序依赖；反例和负收益如实保留。
敏感性扰动应符合参数定义域、可行性和现实尺度，不机械采用统一 ±20%。
留出检验、解析解、边界情形、约束复算、守恒关系、独立数值复算按问题选取。
“看起来合理”是预警检查，不能单独证明模型正确。
验证结论与发布流程见 [validation.md](validation.md)。

## 5. 实现纪律

复用项目既有语言/目录/配置，不强制 Python 或固定 src/common/config.py。
代码入口明确输入、参数、输出；大计算适当落盘，随机过程记录可复现条件。
实际执行后才报告运行成功；无环境或数据时仅交付代码/推导，标注未运行及缺项。
基础检查失败时先修复或回退，不把调参变成掩盖数学/数据错误的手段。
科学结论来自可追溯 Evidence，而不是来自“程序没有报错”。
评估自主追加实验时考虑新信息、题意、稳定性、复杂度与论文解释成本；
不因某次费用略低就默认增加机制。已有明确授权的实验仍按约定范围完成。
