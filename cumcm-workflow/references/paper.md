# 论文与论断来源

论断必须与证据强度匹配。写作路径可简短，但不能丢失数字和结论的来源。

## 1. 统一取材规则

- 重要比较、推论、摘要结论优先建 verified Claim，防止跨实验扩大结论。
- 简单表格/数字可以直接引用 verified Result 的具体字段，不强迫每个数字新建 Claim。
- 题目给定事实/常量可引用 verified Fact；理论性质可引用 verified Model/Fact 及证明。
- obsolete 结果只在原版本和验证仍可核对时作明确标注的历史对照。
- candidate/stale 内容可用于内部讨论或带标记草稿，不得冒充确认事实进入终稿。
- 明确的模型假设不是实验结论，应标注其假设性质与限制。
- 正式采用的主方案及关键假设还须满足 [user-intent.md](user-intent.md) 的用户确认；
  可先写标注为提案的草稿，不能因证据 verified 就把待确认方案写成定稿路线。

维护一个轻量来源映射，可放在稿件注释或 `paper/claim-map.md`：
`章节/表格/数字 -> Claim/Result/Fact ID -> 字段/公式 -> 产物版本`。
二者择一，不重复维护；不要求把内部 Evidence ID 暴露在正式论文正文。

缺数据可先写结构、模型与验证计划，数值位置用 `MISSING VERIFIED RESULT`；
相关问题不得因此标 PAPER_READY。交付终稿前清除所有缺项标记并核对真实性。
`results/summary.md` 只是可选展示，不能作为绕过证据验证的新入口。

## 2. Claim 内容

保存原句、依赖 ID、计算/比较方法、适用范围、局限和拟用章节。
例如“误差降低”必须给出同口径的基线与新结果、分母和百分比算法；
不得把一个划分上的提升写成普遍提升，或把相关性写成因果。
非数值论断可以登记，不为满足“可量化”而编造数字。
验证和依赖失效规则见 [validation.md](validation.md)。

## 3. 同步写作

模型推进时同步写题意、假设、符号和推导；验证通过后填结果、解释与局限。
推荐闭环：问题 -> 数学抽象 -> 模型 -> 求解 -> 结果 -> 解释 -> 验证。
章节按实际题面与官方格式组织，不固定四问，不无故重述算法教科书。
摘要回答问题、所用模型、核心结果和适用结论；没有实质改进不声称创新。

先说明实际问题或观测特点，再说明方法为何适合、必要数学定义及证据支持的效果。
不按每段相同模板机械排列，也不虚构理想化的研究经历。合理性可来自题意、理论、
数据诊断或同条件对照；未经对照的设计动机不能写成已证实的收益。

重要公式附近交代它解决什么、变量范围/单位、为何这样定义以及如何进入下一步。
简单公式一两句即可；复杂索引、风险修正或结算可用真实或明确标为示意的短例。
符号表负责导航，不能替代局部定义。参数含义与真实来源沿 modeling 的记录取材；
经验值不得补写成一月校准或已验证最优。小差异说明绝对差、相对差和实际意义。

使用自然、准确、紧凑的学术中文；减少超长句、抽象名词堆叠和算法教科书介绍。
术语统一保持数学含义，不能简单全局替换使不同变量混同。用户指定原文、保护章节
或只改局部时沿用本次范围；发现实质错误明确指出，不擅自扩大润色。

## 4. 图表与最终检查

图表先明确服务的分析问题。探索图可以显示分布或异常，不要求预先有结论。
正式图表应有可读坐标、单位、图例和一致编码；科研浅色是可调整偏好。
真实数值图使用标准绘图工具，保留数据源、生成代码、图注、所支持的结论和限制。
训练评分图标明训练性质，不通过挑最有利日期或夸大色阶暗示普遍优势。
按所回答的问题取舍图表；重复图、装饰流程图与低价值大表不挤占必答论证。
重要图表用 Figure Evidence 关联输入及生成过程；普通探索图可留在实验产物。

论文到 COMPLETE 是内容齐全；到 REVIEWED 还需数字/引用/单位/规则核对。
任何影响结论的模型修改都需同步来源映射、相关段落与摘要。
冻结后的微小排版修改也要检查最终导出的文件，详见 [submission.md](submission.md)。

从首份可编译稿就按当届规范确认摘要、正文、附录的页数边界和预算，不凭总页数估算。
先压缩重复说明和低贡献图表，保留核心推导及必答内容；局部附录偏好不能变成通用规则。
编辑前保留基线，应用修改前重读用户可能手改的区域，避免覆盖新内容。
检查实际导出中的公式、单位、图表、页码与空白；局部变更检查受影响页，
全局布局变化再扩大视觉检查。编译成功不等于排版可用。
