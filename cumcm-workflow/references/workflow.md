# Workflow 与状态

本文件唯一维护问题/Paper 状态、Gate 条件和压力调度。

## 1. 初始化与建模地图

确认项目根目录、赛题来源、实际问题数量、团队分工、开始/截止时间及时区。
时间未核实则记录 unknown，先做不依赖截止时间的工作，不套用历史 74 小时示例。
先检查已有 STATE/旧版状态，不能覆盖初始化。目录按 [memory.md](memory.md) 创建。

选题时比较题意理解、全题可完成性、数据风险、团队能力和论文空间。
候选题未提供或用户已选题，不强制重新读全部题目或重新评分。
每问记录最少六项：目标、输入、输出、数学结构/约束、验证办法、上游依赖；
候选模型、风险和图表按需补充。问题个数及依赖图来自题面，不固定 Q1-Q4。
分析候选不等于正式选用。选题、主模型及其他关键决策的确认和落盘，
按 [user-intent.md](user-intent.md) 执行；用户已明确指定的方案复用其确认。

从题面逐项定位必答内容：建立模型、求解、解释机制/必要性、评价适用范围、
指定表格等。每项在当前任务或单问说明中关联“题面位置 -> 需要回答的问题
-> 当前版本证据 -> 章节/交付物 -> 缺口”；不另建重复注册簿。
结果表齐全不能替代分析性问题已回答；模型更新后检查原论证能否支持新版本。

## 2. 问题与 Paper 状态

状态指向“当前选用版本”，旧版状态留在快照和 Evidence；状态不是完成百分比。

| 问题状态 | 进入条件 |
|---|---|
| UNREAD | 尚未完成题意解析 |
| ANALYZED | 目标、输入输出、假设和依赖已明确，有可执行方案 |
| IMPLEMENTED | 选定方案已求解或实际运行，存在 candidate 结果和产物 |
| VALIDATED | 当前结果经过适用验证，证据与输入版本一致，无阻断该结论的错误 |
| PAPER_READY | VALIDATED，相关章节已写出，重要论断及数字可追溯 |
| FROZEN | PAPER_READY，已纳入具体冻结提交版本 |

正常路径：UNREAD -> ANALYZED -> IMPLEMENTED -> VALIDATED -> PAPER_READY -> FROZEN。
纯解析模型以实际推导/证明代替程序运行，保留同样的验收语义。
Baseline 和 Improved 是模型的 `maturity` 标签，不是必经状态。
验证合格的 Baseline 可直接 PAPER_READY；改进失败不阻止采用 Baseline。
新候选试验不降低仍有效的选定版本状态；被选结果失效才退回仍可证明的状态。
候选分析/试验可记录在 TASK/Evidence；缺少关键决策确认时不更换 STATE 的当前选用版本，
也不因试验完成或验证通过而将未获确认的方案晋级为正式交付路线。

Paper：EMPTY -> STRUCTURE -> DRAFT -> COMPLETE -> REVIEWED -> FROZEN。
COMPLETE 代表必需内容齐全，不代表已通过一致性审核。
REVIEWED 需审稿记录且无未解决的阻断问题；非关键局限须披露。
影响论断的修改使相关章节回 DRAFT/COMPLETE，复核后才能再次 REVIEWED/FROZEN。

## 3. 八个 Gate

以下 H 是从已确认开始时刻计算的相对小时，时间列仅为 74 小时示例。
正式调度依据本届时间、依赖和任务成本，不能把示例写成官方赛程。

| Gate | 通过条件 | Target | Latest Safe |
|---|---|---|---|
| G1 选题 | 用户已确认题目，基本可行性与主要风险已明确 | H3 | H5 |
| G2 框架 | 所有必答问目标/接口/依赖清楚，已建论文骨架 | H8 | H12 |
| G3 首个闭环 | 至少一个关键问有真实 candidate 结果并完成基本运行/边界检查 | H24 | H30 |
| G4 全题打通 | 所有必答问的当前选定结果 VALIDATED，可保留 Baseline | H36 | H44 |
| G5 质量收敛 | 关键验证和局限已交代，改进采纳或有据放弃，主要论断可用 | H48 | H56 |
| G6 完整论文 | Paper REVIEWED，论断/结果/代码一致，阻断问题已处理 | H64 | H68 |
| G7 冻结 | 冻结清单、可恢复版本及提交前检查齐备，尚不要求已提交 | H70 | H72 |
| G8 提交 | 所有适用提交步骤完成并获得可追溯回执 | H73 | H74 |

Gate 是已验收的项目里程碑，不等同于“最慢问题状态”。
单问可提前推进；允许提前写论文、并行验证。时间过去不会自动通过 Gate。
G5 不要求更复杂模型胜出；不存在适用敏感性分析时记录理由，而不是造实验。
涉及正式采纳、替换或缩减必答范围的 Gate 更新仍须核对关键决策确认；
Pressure、止损或冻结均不授予越过该确认的权限。
因用户策略跳过建议流程时记录例外，未满足条件不能标成 PASSED。

STATE 的 gate 表示最近有记录支持的已验收里程碑。
尚无里程碑通过时取 null；通过后取 G1-G8，不用 G1 代表“正在选题”。
当前正在解决的阶段和待验收条件写在 Next Actions，不以同一个字段同时表示目标与完成状态。旧记录语义不明确时
注明待核对，不按产物数量自动晋级。通过 Gate 时写唯一编号快照；
若关键证据失效，标明历史 Gate 需要重验，重新开相关 TASK，不抹去历史通过记录。

## 4. Pressure 与 Freeze 分离

Pressure 只有 NORMAL / PRESSURE / CRITICAL。
Freeze 是独立的 `freeze.active` 及版本清单，见 [submission.md](submission.md)。
时间不足或问题完成不能自动声称已冻结；冻结时也可能发生 CRITICAL 错误。

先辨别当前是比赛执行、赛后复盘还是局部维护。复盘/维护不因 STATE 留着过去截止
而启用临赛收敛策略。比赛执行时再根据已核实的具体截止重算压力；字段更新时间
不证明压力仍适用。不得由“已过截止”推断已提交，也不猜测延期或上传期限。

估计 `remaining = deadline_at - 当前时间`，不要沿用旧 STATE 的“剩余 30h”。
同时估计必需任务依赖链成本及验证、排版、上传缓冲；并行任务不简单求和。

| Pressure | 判断信号 | 默认策略 |
|---|---|---|
| NORMAL | 必需工作和缓冲可完成，无关键交付风险 | 可探索、比较、适度改进 |
| PRESSURE | 缓冲被侵蚀、Gate 明显落后或论文滞后 | 完成缺失问、接口、验证与论文 |
| CRITICAL | 必需工作预计无法按时完成，或关键错误危及交付 | 修错、缩小范围、采用有效 Baseline、保护提交版本 |

工时未知时注明不确定，安排短时间诊断，不能据虚构估计给精确压力结论。
压力下降要有新的完成/验证证据，不因一次乐观估计反复切档。

## 5. 优先级与止损

优先解决使结果不可信的 Critical 错误和必要提交障碍，再处理阻塞依赖、未完成问、
论文缺失及必要验证，最后才是强化、调参和装饰。综合影响和成本，不机械套乘法评分。

每个探索 TASK 定义预算、成功信号、停止条件和回退产物。
建议 NORMAL 60-120 分钟、PRESSURE 30-60 分钟、CRITICAL 只做短验证或必要修复；
这些是可调整策略，不是到点删除任务或停止所有工作的硬命令。
止损时保留失败命令、关键错误和复用产物；普通止损记 TASK，
只有实质阻断才建 ISSUE。不能为了遵守止损而把未验证结果晋级。
